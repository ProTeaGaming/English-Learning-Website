# VocabLarry Professional Environment — Grammar Browse + Topic Detail Visual Retrofit Design

## Context

VocabLarry Professional Environment (VLPE) is a parallel Django-templating rebuild of production VocabLarry (`VocabLarry/vocablarry.html`, a single-file client-side SPA — read-only reference material, never edited). Three prior visual-retrofit sub-projects are complete and merged: Nav & Routing Skeleton, Vocab Browse/Category/Word, and Vocab Quiz. This is the fourth: **Grammar Browse** (`grammar/browse.html`, view `grammar_browse`) and **Grammar Topic Detail** (`grammar/topic_detail.html`, view `grammar_topic_detail`).

Both VLPE pages currently exist but are visually bland and functionally thin compared to production:
- Browse is a flat, ungrouped topic grid with a text search box and a `<select>` stage filter. No section grouping, no CEFR filter, no status filter, no theme-colored cards.
- Topic Detail renders `intro`/`rule`/`table`/`examples`/`tip` lesson blocks with zero styling — plain divs/tables.

**Explicit instruction for this retrofit (given directly by the user, overriding the more conservative defaults used in prior retrofits):** match production **exactly** — visual design and functional behavior — including two pieces prior retrofits would normally have simplified away: the GSAP-driven scroll-scrub effect on rule cards (reproduced here in plain JS, not by adding GSAP — see Decisions) and the per-section Unsplash hero images (a genuinely new external dependency, accepted deliberately here). The only structural difference from production is architectural, not visual: this is real multi-page Django templates/views instead of one client-rendered SPA page, consistent with every prior VLPE retrofit.

**Source of truth:** `VocabLarry/vocablarry.html` (local, confirmed current and unmodified this session, verified to match the live site). **Not** `C:\Users\TGC\Downloads\vocablarry-deploy.zip` — independently confirmed stale earlier this session (dated July 14, missing already-shipped work).

## Decisions

- **Section grouping uses the `GRAMMAR_SECTIONS` slug→section-name override map, not the topic's own `tag` field.** Production's actual grouping logic is `GRAMMAR_SECTIONS[topic.slug] || topic.tag` — and critically, **all 47 topics have an entry in `GRAMMAR_SECTIONS`**, so the `tag` fallback is never actually exercised in practice. Several topics' raw `tag` values diverge from their assigned section (e.g. `irregular-verbs` has `tag: "Tenses"` — consistent — but `phrasal-verbs` has `tag: "Verbs"` while its `GRAMMAR_SECTIONS` entry is `"Verb Patterns & Modals"`; `dependent-prepositions` has `tag: "Prepositions"` vs section `"Word Forms & Prepositions"`; `comparison-structures` has `tag: "Comparison"` vs section `"Adjectives & Adverbs"`; `subject-verb-agreement` has `tag: "Nouns"` vs section `"Nouns, Pronouns & Determiners"`). The full 47-entry map, plus the 12-entry `GRAMMAR_SECTION_ORDER` (canonical display order) and `GRAMMAR_SECTION_ICONS` map, must be ported verbatim into the Django view as Python constants. `topic.tag` is not independently displayed anywhere in the browse UI (the card's tag-shaped pill shows a question-count label, not the raw tag) — it only ever matters as this grouping fallback.
- **All filtering happens server-side**, unlike production's client-side filtering — consistent with how the Vocab Category retrofit already handles CEFR/status filtering in VLPE. Query params: `q` (search, already exists), `stage` (already exists, now also drives the headline-bar buttons instead of a `<select>`), `cefr` (new), `status` (new, authenticated users only — reuses the same Mastered/In Progress/Not Started semantics as `grammarTopicStatus`).
- **Theme color assignment is round-robin per section, computed server-side at render time** (not stored on the model), exactly matching production's `GRAMMAR_CARD_THEMES[themeIdx++ % length]` — the 15-color list and its cycling order are ported verbatim so a given topic gets the same color on every page load (deterministic: same topic order in, same theme out).
- **Accordion sections start collapsed, independently toggleable** (not single-open-at-a-time) — matches production's actual behavior exactly (verified in source: each section's click handler only toggles its own `.open` class, never touches sibling sections).
- **CEFR badges reuse VLPE's existing 12-level `.cefr-badge` system** (already built for Vocab Browse) rather than porting production's separate `cefrRangePillHtml`/range-parsing logic — VLPE's `GrammarTopic.cefr` stores a single exact level per topic (confirmed via the imported JSON), never a range like production's `"A1–B1"` capability, so the range-handling branch of production's pill logic is dead code for this dataset and isn't needed.
- **The GSAP ScrollTrigger pin/scale/blur-on-scroll effect on rule cards is reproduced in plain JS — GSAP itself is not added as a dependency**, consistent with this project's standing rule (already applied in the Vocab Quiz retrofit for card-entrance/count-up animations). Approach: on `scroll` (rAF-throttled), for every `.gram-stage` card except the last, compute a 0–1 progress value from `getBoundingClientRect()` against the same start/end triggers production uses (`start: card top reaches viewport top+100px` → `end: last card's top reaches viewport top+120px`, scrubbed continuously), then linearly interpolate and apply `transform: scale(...)`, `filter: blur(...) saturate(...)`, and `opacity` as inline styles — reproducing the visual choreography without the library. Production's *other* reveal effect (fade-in for `intro`/`table`/`examples`/`tip` blocks) already uses plain `IntersectionObserver` in production itself, so that part ports directly with no GSAP-equivalence work needed.
- **The Unsplash hero images are included**, ported verbatim: the per-section photo-ID map (`GRAMMAR_SECTION_IMAGES`, 12 sections × 2 IDs each), the 3-ID fallback pool, and the `grammarImgUrl(id)` URL-building helper (`https://images.unsplash.com/photo-{id}?auto=format&fit=crop&w=900&q=80`). This is a new external network dependency for VLPE — no other page currently loads third-party images — accepted here per explicit instruction.
- **Debug/admin content-editing controls are excluded** (the ✎/✕ edit/delete buttons on cards, blocks, and questions; the "+ Add topic"/"+ Add block"/"+ Add question" cards; the "Manage questions" panel). These are production's own internal content-authoring tooling gated behind a `body.debug-on` class that end users never see enabled — not a real user-facing feature, and VLPE has no equivalent debug-mode infrastructure or content-editing backend. Out of scope for a visual/functional retrofit aimed at the real user-facing experience.
- **New icons added to the SVG sprite** in `templates/base.html`: `i-clock`, `i-message`, `i-type`, `i-palette`, `i-puzzle`, `i-activity`, `i-megaphone`, `i-dice`, `i-scroll` (section icons not already present) and `i-sprout`, `i-trend-up`, `i-grad-cap`-family icons for the headline-bar stage buttons (some already present from other pages — reuse, don't duplicate), `i-clipboard` and `i-lightbulb` for table/tip block icons, `i-chevron-down` or equivalent if the accordion chevron needs a dedicated icon (production uses a plain `›` character, not an SVG — ported as plain text, no new icon needed there).
- **`.headline-bar`/`.headline-btn` is new CSS** (not currently in VLPE anywhere) — ported verbatim for the Basic/Intermediate/Advanced stage filter, using VLPE's existing `--gram-basic`/`--gram-inter`/`--gram-adv` custom properties (already defined in `base.css`'s root token block, unused until now).

## Architecture

Both pages remain real Django views/templates — no move toward client-side rendering or a shared API-driven JS engine like production's SPA. `grammar_browse` (`config/views_grammar.py`) is substantially rewritten: fetches all topics, computes each one's section via the ported `GRAMMAR_SECTIONS` map, groups into `GRAMMAR_SECTION_ORDER`'s sequence, applies `stage`/`cefr`/`status`/`q` filters server-side, assigns round-robin theme classes per section, computes per-section progress (`done_count / topic_count`), and passes a nested structure (list of sections, each with its filtered+themed topic list and progress %) to the template. `grammar_topic_detail`'s view logic is essentially unchanged (already fetches `topic` + ordered `blocks` correctly) — only the template, CSS, and new JS (reveal-on-scroll + scroll-scrub) change.

New CSS in `static/css/grammar.css`: `.headline-bar`/`.headline-btn`, `.section-block` family (accordion), the 15 `.t-tX`/`--tb`...`--tnavy` theme classes (shared constants, could live in `base.css` since they're generically reusable the way `.cat-card`'s `--accent-c` fallback already anticipates — decided at plan time based on whether other pages might reuse them), `.gram-stage` family (rule cards + flip layout + image panel), `.gram-block`/`.gram-table`/`.gram-ex`/`.gram-tip` (other block types), `.gram-chip`/`.gram-s-basic`/`.gram-s-inter`/`.gram-s-adv` (status-style chips), `cat-view-title-row`/`cat-view-icon`/`cat-view-name`/`cat-view-sub` (topic detail header — reuses the `cat-view-*` naming production itself uses, distinct from `word-detail-*` which VLPE already has for vocab word pages).

New JS: a small `static/js/grammar-browse.js` for the accordion toggle + all four filter types (stage/cefr/status/search — though search stays a real GET-param form submit like today, not live client-side filtering, since VLPE's established pattern is server-rendered filtering, not a client-side re-render); a small addition to a `static/js/grammar-topic.js` (or inline, depending on plan-time file-size judgment) for the reveal-on-scroll IntersectionObserver and the scroll-scrub controller.

## Components

### Browse page (`grammar/browse.html`)

- `.headline-bar`: "All" / "Basic" / "Intermediate" / "Advanced" buttons (icons: sprout/trend-up/grad-cap, matching production), driving the same `stage` query param the current `<select>` already uses — replaces the `<select>`, doesn't add alongside it.
- `.filters` panel (existing pattern) containing: a dynamic section-chip row (only sections that have at least one topic currently in the pool are shown as chips — matches production, which builds this list from the actual topic data each render), a CEFR chip row (reusing `.chip.active[data-grammar-cefr="X"]`, extending `base.css`'s 12 CEFR rules the same way the Vocab Quiz retrofit added `data-quiz-cefr`), a status chip row (Mastered/In Progress/Not Started, authenticated users only — reuses `data-browse-status` colors already defined), search input (existing `q` param, unchanged), and a "Clear filters" link.
- `.section-block` accordion: one per non-empty section, in `GRAMMAR_SECTION_ORDER` sequence, each with a numbered header (progress bar + %, topic count, chevron) and a collapsible body containing a `.cat-grid` of themed `.cat-card`s (same card anatomy as Vocab Category's cards: tag pill with icon + question count, CEFR badge, medal-or-progress-bar footer) — reusing `.cat-card`/`.cat-grid`/`.cat-tag`/`.cat-pbar-row`/`.cat-medal` wholesale from `vocab.css`, with the new `.t-tX` theme class added per card.

### Topic Detail page (`grammar/topic_detail.html`)

- Header: `.cat-view-icon` (theme-colored circle with the section's icon), `.cat-view-name` (theme-colored title) + CEFR badge, `.cat-view-sub` (question count · section label), "Practice this topic" button (existing, restyled).
- Lesson body: `rule` blocks render as `.gram-stage` cards (numbered "Rule 01" etc., alternating flip layout, Unsplash image panel, theme-colored accents) inside a `.gram-stack` wrapper; `intro`/`table`/`examples`/`tip` blocks keep their existing block-type branching in the template but get real `.gram-block`/`.gram-table`/`.gram-ex`/`.gram-tip` styling, plus the plain-JS reveal-on-scroll fade-in.
- Bottom: "Practice this topic" repeated + "Back to all" link (existing `.cat-bulk-actions` pattern, already used on Vocab Category word-list page).

## Data Flow

Unchanged endpoint/URL contract (`grammar_category_list`, `grammar_category_detail`) and unchanged underlying data (`GrammarTopic`, `GrammarLessonBlock` — no new models/migrations). New server-side computation only: section assignment (`GRAMMAR_SECTIONS` lookup), theme assignment (round-robin index), filter application (stage/cefr/status/q), progress computation (per-section done-count). All of this reads existing `request.user.grammar_map` data (already used by the current unstyled view) — no new persistence.

## Error Handling

Unchanged trigger conditions (no topics match filters → existing "no topics match" messaging, restyled; unknown slug → existing 404 via `get_object_or_404`). Unsplash image `<img>` tags get a plain CSS `background-color` fallback (matching the card's theme color) so a failed image load doesn't leave a blank hole — no JS-based retry/fallback logic, matching the low-stakes nature of a decorative background image.

## Testing

Python tests: section-grouping correctness (a topic with a `tag`/`GRAMMAR_SECTIONS`-divergent entry lands in the `GRAMMAR_SECTIONS`-designated section, not its raw `tag`), each filter type individually and in combination, theme-assignment determinism (same input order → same theme sequence), accordion markup (all sections present, correct collapsed-by-default state is a CSS/JS concern not directly assertable server-side — assert the `.section-block` markup and data attributes are correct), CEFR/status chip attribute correctness, rule-card numbering and image-URL correctness, non-rule block type rendering.

Explicitly needs real-browser (Playwright) verification, not just Python tests: accordion expand/collapse (independent per-section toggle), all filter combinations' visual chip states, the scroll-scrub pin/scale/blur choreography (this is the one genuinely novel interaction in this retrofit — must be watched scrolling in a real browser, both for correctness of the math and for visual smoothness), the reveal-on-scroll fade-ins, Unsplash images actually loading, both themes, and the "Practice this topic" button still correctly launching `grammar_category_quiz` (unchanged endpoint, but should be re-confirmed after the header/layout changes).

## Explicitly Out of Scope

- Debug/content-authoring UI (✎/✕ controls, "+ Add" cards, "Manage questions" panel) — production's internal tooling, not a real user feature.
- Grammar Quiz retrofit (`grammar/quiz_setup.html`, `grammar/quiz_play.html`, `grammar/topic_quiz.html`) — separate, already-planned next sub-project.
- Grammar Word page (`grammar/word.html`) — separate, already-planned future sub-project (irregular verbs/plurals/comparisons/linkers/idioms reference).
- Any change to quiz-taking logic, scoring, or the `GrammarQuestion`/`GrammarLessonBlock` data model.
- i18n: no new translation work beyond what's already wired (chrome/nav labels) — matches every prior retrofit's scoping.
